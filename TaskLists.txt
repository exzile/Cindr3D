## Fillet & Chamfer — Accuracy / Reliability / Rollback Improvement Plan
## Based on Fusion 360 SDK deep audit (2026-05-20)
## Ordered by ROI: fix architecture first, then broken params, then reliability,
## then feature parity. Architecture must come first because everything else
## depends on fillets/chamfers being proper feature nodes with stored params.
# ============================================================================


# ══════════════════════════════════════════════════════════════════════════════
# PHASE 0 — Architecture: Non-destructive feature model + undo/rollback
# ══════════════════════════════════════════════════════════════════════════════
# Currently fillets/chamfers are DESTRUCTIVE MESH MUTATIONS on the parent
# feature. applyEdgeCut replaces the parent's mesh in-place and disposes the
# old geometry. This means:
#   • No fillet/chamfer entry exists in the feature tree — the operation is
#     invisible in the timeline
#   • Undo can't recover the mesh — snapshotCADState strips meshes to
#     undefined, so on restore the old pre-fillet body is gone
#   • Suppression is cosmetic — flips a boolean, doesn't re-evaluate geometry
#   • rollbackIndex is render-only — hides features past the bar but doesn't
#     replay the feature tree
#   • Edit doesn't work — updateFeatureParams stores new radius but never
#     re-runs the geometry
#
# Fusion's approach: every fillet/chamfer is a separate TimelineObject with
# stored params + edge references. rollTo(true) repositions the timeline
# marker before the feature, and the kernel replays forward from there.
# isSuppressed triggers re-evaluation. deleteMe() removes + re-evaluates.

[ ] 0a. Fillet/chamfer as proper feature nodes
#   Instead of mutating the parent feature's mesh, create a new feature node:
#     { type: 'fillet', params: { radius, mode, edgeIds, ... },
#       parentFeatureId: '<source body>', mesh: <result> }
#   The parent feature retains its ORIGINAL mesh (never disposed).
#   The fillet feature's mesh is the CSG result computed from the parent's mesh.
#   Store the complete FilletParams/ChamferParams on the feature so they can
#   be edited and replayed.
#
#   Impact: FilletDialog.handleConfirm, ChamferDialog.handleConfirm,
#   applyEdgeCut.ts, ExtrudedBodies.tsx (render the fillet feature's mesh
#   instead of the parent's when the fillet is active and not suppressed).

[ ] 0b. Source mesh preservation
#   The parent feature's mesh must be preserved (never disposed) when a
#   downstream fillet/chamfer is applied. Currently applyEdgeCut clones the
#   source geometry then replaces the parent mesh. Instead:
#     1. Clone the parent mesh for CSG input (already done)
#     2. Store the CSG result on the NEW fillet feature's mesh
#     3. Leave the parent's mesh untouched
#     4. Rendering logic: show the LAST non-suppressed feature in the chain
#   This is the "non-destructive" pattern that enables undo/suppress/delete.

[ ] 0c. Feature replay engine
#   When a fillet/chamfer is suppressed, deleted, or edited:
#     1. Find the parent feature (the source body)
#     2. Find all fillet/chamfer features that depend on it (ordered by index)
#     3. Replay from the parent's original mesh, applying each non-suppressed
#        fillet/chamfer in sequence
#     4. Update each feature's mesh with the intermediate result
#   This is the minimal parametric re-evaluation engine. It extends the
#   existing recomputeBooleanDependents pattern to cover fillet/chamfer.
#
#   Fusion SDK parallel: TimelineObject.rollTo(true) + forward replay.

[ ] 0d. Fix undo mesh recovery
#   snapshotCADState strips meshes to undefined. On restore, liveMeshById
#   lookup matches by feature ID — but after a fillet, the parent's old mesh
#   is disposed, so restoration gets the post-fillet mesh (wrong).
#   Fix: when fillets are proper feature nodes, the parent mesh is never
#   disposed. Undo restore finds the correct live mesh for both parent and
#   fillet features. If mesh is missing, trigger replay from params.

[ ] 0e. Feature health states
#   Every feature should report its health: Healthy / Warning / Error.
#   When computeEdgeCutGeometry fails or partially succeeds, store the
#   diagnostic on the feature node: feature.healthState = 'warning',
#   feature.healthMessage = '3 of 5 edges could not be processed'.
#   Surface this in the feature tree with an icon (green/yellow/red dot).
#   Fusion SDK: Feature.healthState(), errorOrWarningMessage()


# ══════════════════════════════════════════════════════════════════════════════
# PHASE 1 — Bugs: params collected but geometry ignores them
# ══════════════════════════════════════════════════════════════════════════════
# These are the most urgent after Phase 0 — the UI already shows controls
# for each one, but the commit path silently ignores them.

[ ] 1. Wire edit fillet/chamfer → re-run geometry
#   FilletDialog.tsx line 426: editing branch calls updateFeatureParams but
#   NEVER calls commitFillet. Editing is a complete no-op — mesh not touched.
#   Fix: after Phase 0, editing updates feature.params and triggers the
#   replay engine (0c) which re-runs geometry from the parent mesh.
#   Same fix applies to chamfer editing.

[ ] 2. Wire chord-length fillet into buildFilletCutter
#   FilletDialog collects chordLength but handleConfirm (line 446) calls
#   commitFillet(r, 4) — always the global radius, never chordLength.
#   Fix: when mode === 'chord-length', convert per-edge at CSG time:
#   r = chordLen / (2 * sin(φ/2)) where φ = dihedral angle (already
#   computed as 'phi' in buildFilletCutter).
#   Fusion SDK: ChordLengthFilletEdgeSetInput.chordLength

[ ] 3. Wire variable-radius fillet into buildFilletCutter
#   startRadius/endRadius collected but commitFillet uses constant radius.
#   Fix: when r1 ≠ r2, buildFilletCutter builds a ConeGeometry (frustum)
#   instead of CylinderGeometry. Parameterize: r(t) = r1 + t*(r2 - r1).
#   Setback per end: sb(t) = r(t) / tan(phi/2).
#   Also: add mid-point radius support (addMidPosition/deleteMidPosition).
#   Fusion SDK: VariableRadiusFilletEdgeSetInput.setMidRadii(radii[], positions[])

[ ] 4. Add Flip button for two-distance AND distance+angle chamfer
#   Which face is "face 1" vs "face 2" depends on arbitrary triangle scan
#   order in resolveEdge. User has no control.
#   Fix: add Flip toggle to ChamferDialog for both two-dist and dist-angle
#   modes. On confirm, when flipped, swap d1/d2. Store isFlipped in params.
#   Fusion SDK: TwoDistancesChamferEdgeSet.isFlipped(),
#               DistanceAndAngleChamferEdgeSet.isFlipped()

[ ] 5. Surface failed-edge count in status bar
#   When resolveEdge fails, the edge is silently skipped.
#   Fix: computeEdgeCutGeometry returns { geometry, failedCount }.
#   applyEdgeCut surfaces "N of M edges could not be processed" via
#   setStatusMessage. After Phase 0e, also store on feature.healthState.


# ══════════════════════════════════════════════════════════════════════════════
# PHASE 2 — Reliability: silent failures, junction artifacts, UX
# ══════════════════════════════════════════════════════════════════════════════

[ ] 6. Wire propagate → tangent edge auto-expansion
#   "Propagate Along Tangent Edges" checkbox is stored but never applied.
#   Fix: after edge picker returns a set, walk geometry.userData.topology
#   to find all tangent-connected edges (dihedral < 5°). Add them to the
#   working set before passing to computeEdgeCutGeometry.
#   Fusion SDK: BRepEdge.tangentiallyConnectedEdges() — returns the full
#   tangent chain, already ordered. We build the equivalent walk on our
#   extracted topology (posRegions + region normals).

[ ] 7. Rolling-ball corner sphere at multi-edge junctions
#   When 3+ filleted edges meet at one vertex, each edge is cut independently
#   leaving a triangular gap at the corner.
#   Fix: detect shared endpoints across filleted edges. For each vertex
#   shared by ≥ 3 filleted edges, CSG-subtract a sphere of radius r.
#   Fusion SDK: isRollingBallCorner on FilletFeatureInput

[ ] 8. Adaptive segment count (not hardcoded to 4/48)
#   commitFillet(r, 4) always passes segments=4 → radialSeg=48.
#   Fix: compute radialSeg from arc length:
#     arcLen = r * (π - phi)
#     radialSeg = clamp(round(arcLen / targetSegLen), 16, 128)
#     targetSegLen ≈ 0.5mm for commit, 2mm for preview

[ ] 9. Convex/concave edge classification
#   Fusion SDK: BRepBody.concaveEdges() / convexEdges() — pre-classified
#   edge sets. Critical for rule fillets and for visual feedback (showing
#   different colors for concave vs convex edges in the overlay).
#   Fix: after extractEdgeTopology, classify each edge by the cross product
#   of its two adjacent face normals dotted with the edge midpoint→face
#   centroid vector. Store concave/convex flag on ModelEdge.


# ══════════════════════════════════════════════════════════════════════════════
# PHASE 3 — Feature parity: Fusion capabilities we don't have
# ══════════════════════════════════════════════════════════════════════════════

[ ] 10. Chamfer corner type selector
#    Fusion: ChamferCornerTypes — ChamferCornerType (patch), MiterCornerType
#    (extend+intersect), BlendCornertype (smooth blend).
#    Fix: add Corner dropdown to ChamferDialog (Patch / Miter). For Miter:
#    detect shared vertices, compute chamfer-face intersection lines, clip.

[ ] 11. Asymmetric fillet (different offsets each side)
#    Fusion SDK: AsymmetricFilletEdgeSetInput — offsetOne, offsetTwo, isFlipped.
#    Fix: add Asymmetric mode to FilletDialog. buildFilletCutter supports
#    two independent setback values with cylinder axis shifted off bisector.

[ ] 12. Full-round fillet (3-face rolling ball)
#    Fusion SDK: FullRoundFilletFeatureInput — centerFace + sideOneFaces +
#    sideTwoFaces + areAutomaticSideFaces (auto-infer from adjacency).
#    Fix: switch picker to face-selection mode in full-round mode. Compute
#    inscribed circle from three-face corner. Build cutter from result.

[ ] 13. Rule fillet (fillet all edges of a selected face/feature)
#    Fusion SDK: RuleFilletFeatureInput — setByAllEdges(faces[]) or
#    setByBetweenFacesOrFeatures(set1[], set2[]). Also topologyType filter
#    (RoundsAndFillets / RoundsOnly / FilletsOnly).
#    Fix: add face-picker mode in FilletEdgeHighlight. Click face → extract
#    all topology edges of that face → add to selection in one shot.

[ ] 14. G2 curvature continuity + tangency weight
#    Fusion SDK: SurfaceContinuityTypes — G0 (Connected), G1 (Tangent),
#    G2 (Curvature). Plus tangencyWeight 0.1–2.0 on every fillet edge set.
#    G2 requires generating a curvature-continuous blend surface instead of
#    a circular arc (the cylinder cutter approach is inherently G1). This is
#    a significant geometry engine change — the cutter would need to be a
#    NURBS surface or a higher-order polynomial blend.
#    Tangency weight scales how far the blend extends along each face.

[ ] 15. Stable edge identity (entity tokens)
#    Fusion SDK: BRepEdge.entityToken — survives save/reload. Our edge IDs
#    are world-space vertex coordinates in strings — they break when the body
#    is translated, rotated, or scaled.
#    Fix: use a hash of the edge's LOCAL-space endpoints relative to the
#    body's bounding box, making IDs transform-invariant. Store on the
#    feature node so edge references survive across sessions.

[ ] 16. Feature reordering with dependency validation
#    Fusion SDK: TimelineObject.canReorder(beforeIndex) / reorder(beforeIndex).
#    Our reorderFeature exists but has no dependency checking — you can move
#    a fillet before its parent body, breaking the chain.
#    Fix: validate that a feature's dependencies all appear before it in the
#    array before allowing reorder. Block and surface a warning if not.
